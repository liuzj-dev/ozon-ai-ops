# ozon-ai-ops

> AI-powered automation toolkit for Ozon cross-border e-commerce operations

把 Ozon 跨境店铺的日常运营流程，用 LLM 自动化掉。面向真实的铺货场景，不是 demo。

---

## 1. 问题

做 Ozon 俄罗斯市场，运营每天要花大量时间在三件重复劳动上：

- **写不了俄语文案** —— 中文翻译成俄语后不符合当地人阅读习惯，转化率低
- **选品靠感觉** —— 没有数据支撑，上架后才发现竞争激烈或定价错位
- **算不清真实利润** —— 平台佣金、跨境物流、卢布汇率层层扣减，手工算容易出错

以一个 SKU 为例，手工完成「选品调研 → 撰写俄语 listing → 核算利润」大约需要 **__ 分钟**。

## 2. 方案

```
                    ┌─────────────────────┐
   商品参数表  ───▶  │  模块 A：Listing 生成 │  ───▶  俄语标题/卖点/描述
                    └─────────────────────┘
                    ┌─────────────────────┐
   Ozon 类目数据 ──▶ │  模块 B：选品情报     │  ───▶  选品评分表
                    └─────────────────────┘
                    ┌─────────────────────┐
   订单流水    ───▶  │  模块 C：利润核算     │  ───▶  日报 / 月报
                    └─────────────────────┘
```

| 模块 | 输入 | 输出 | 状态 |
|---|---|---|---|
| **A. Listing 生成** | 中文商品参数表 | 俄语标题 / 卖点 / 描述 / 关键词 | ✅ 已完成 |
| **B. 选品情报** | Ozon 类目热销数据 | 竞争度 + 定价带 + 选品评分 | 🚧 开发中 |
| **C. 利润核算** | 订单流水 | 扣除佣金/物流/汇率后的利润表 | ⏳ 计划中 |

## 3. 效果

实测 3 个真实 SKU（每个含标题 + 5 条卖点 + 描述 + 关键词）：

| 指标 | 手工 | 本工具 | 提升 |
|---|---|---|---|
| 单 SKU 文案耗时 | 约 25 分钟 * | **2.5 秒** | **约 600x** |
| 100 SKU 批量生成 | 约 42 小时 | **约 4 分钟** | **约 600x** |
| Token 消耗 | —— | 约 800 / SKU | —— |
| 文案语言质量 | 需译者参与 | 符合当地表达习惯 | —— |

\* 手工口径：中文撰写 + 机器翻译 + 俄语校对。不掌握俄语的运营者实际上无法独立完成这条链路。

**首次运行实测数据：**

```
3 个 SKU 全部成功    耗时 7.4 秒
Token 用量：输入 1132 / 输出 1258
```

生成样例见 [`examples/`](examples/)。

## 4. 技术

| 组件 | 选型 | 为什么 |
|---|---|---|
| LLM | DeepSeek API | 中文理解好、价格低、OpenAI 兼容 |
| 数据处理 | pandas | —— |
| 输出 | openpyxl | 直接产出可上传的 Excel |
| 配置 | python-dotenv | Key 与代码分离，避免泄露 |

**关键设计：**
- **结构化输出** —— 用 JSON mode 强制模型返回固定字段，避免解析自由文本
- **失败不中断** —— 单条失败重试 3 次后跳过，整批继续跑完
- **成本可见** —— 每次运行统计 token 用量，方便核算单条成本

## 5. 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 配置 API Key
copy .env.example .env        # Windows
# 然后编辑 .env，填入你的 DEEPSEEK_API_KEY

# 3. 运行
python main.py
```

输出文件在 `data/output/listings_时间戳.xlsx`。
